# Unity 桥接宿主（可选组件）

这是一个可选的补充组件：装进 Unity 工程后，编辑器会把**当前实际生效的**全局着色器关键字与全局宏（定义 / 未定义）实时告诉 MicroShader 语言服务器，让诊断从「按平台表推定」变成「按编辑器实测」。

不装也照常使用：诊断、补全、跳转完全不受影响，只是宏状态按平台默认值推定。

为什么要它：`_MAIN_LIGHT_SHADOWS`、`_ADDITIONAL_LIGHTS` 这类全局关键字，`SHADER_API_D3D11`、`UNITY_COLORSPACE_GAMMA` 这类全局宏，都由编辑器与工程设置动态决定，影响 shader 里哪些分支被当作「生效」参与诊断。语言服务看不到这些运行期状态：不装桥接时只能按平台表推定，装上后用的就是你编辑器里的实测值。

组件本体是 `client/unity/MicroShaderBridge/` 下的一组 Unity 编辑器脚本，不需要编译、不需要联网。前提是语言服务端已装好（VS Code 扩展或 Sublime 接入，任一即可）。

## 一、安装与卸载

安装＝整目录复制，零依赖：

1. 把 `MicroShaderBridge/` **整个文件夹**复制到 Unity 工程的**任意 `Editor` 目录**下，例如 `<Project>/Assets/Editor/MicroShaderBridge/`。

   - 路径中必须有一个目录叫 `Editor` —— Unity 靠目录名决定脚本是否只在编辑器里编译。
   - 每个文件自带 `#if UNITY_EDITOR` 保护，即使误放到 `Assets/` 根目录也不会污染播放器构建。
   - 不依赖任何 Package、Prefab、ScriptableObject，也不需要 UniTask。

2. 回到 Unity（或点 `Assets → Refresh`）。Console 出现下面这行（端口每次分配都不同，这里的 60522 只是示例）：

   ```
   [MicroShader] 桥接已监听 127.0.0.1:60522（transport=tcp，动态端口），发现文件：<Project>/Library/MicroShader/endpoint.json
   ```

3. 语言服务端（`UnityShaderLsp.exe`，随编辑器集成一起安装）会自动发现并连接。VS Code 的 Output 面板出现：

   ```
   Vfs: Unity 桥接（启动快照）：已连接 Unity（pid …，127.0.0.1:…，已收 1 帧 / 应用 1 次）…
   ```

看到上面两行输出，就说明桥接已经工作。装与不装，诊断条目应逐条一致 —— 桥接只改变判断依据，不会凭空多出或少掉告警。

**卸载**：先退出 Unity，再删除 `MicroShaderBridge/` 目录和 `Library/MicroShader/endpoint.json`。也可以先在菜单里「启用/禁用」关掉桥接（关闭时会顺手删掉发现文件），再删目录。

## 二、它是怎么连上的

Unity 会先把「我的监听地址」写进工程的 `Library/MicroShader/endpoint.json`（发现文件），然后在本机回环端口上监听；语言服务读到这个文件后主动连上来 —— 方向是「语言服务外连 Unity」，你不需要在 Unity 里填任何服务器地址。重编译脚本时桥接会短暂断开、编译完成后自动恢复，不需要手动操作。

发现文件放在 `Library/` 而不是 `Temp/`：`Temp/` 在关闭编辑器时会被清空，也表达不了「这是哪个工程」；`Library/` 让语言服务在编辑器重启后仍能分辨该连谁。它是一份普通的文本 JSON，想知道当前端口，用菜单「打开发现文件」看里面的 `port` 字段即可。

## 三、菜单

菜单位置：`Tools → MicroShader → Unity Bridge`。

| 菜单项 | 作用 |
| :--- | :--- |
| `状态` | 打印启用/运行状态、端口、客户端数、广播次数、当前载荷 |
| `启用/禁用` | 切换开关（默认启用，开关状态会被记住）；关闭时删除发现文件 |
| `重启监听` | 手动重新绑定端口并重写发现文件 |
| `立即广播` | 强制重算载荷并广播一次（含重写发现文件） |
| `打开发现文件` | 在文件资源管理器里定位 `endpoint.json` |
| `详细日志开关` | 打印客户端接入/断开、编译边界等细节，排障用 |

## 四、广播协议要点

给需要自己对接桥接的人（普通用户可跳过）：

- 线格式是**换行分隔 JSON（LDJSON）**，一行一帧。
- 每个客户端连上先收到一份**完整快照**；之后只在状态变化时才发差异帧 —— 内容没变就一帧都不发。
- 载荷分三部分：编辑器当前**启用**的全局关键字 `activeKeywords`；应当**被定义**的宏 `globalDefines.defined`（形如 `"X"` 或 `"X=1"`）；应当**显式 `#undef`** 的宏 `globalDefines.undefined`。「不定义」本身也是需要如实表达的结论，例如 Linear 色彩空间下会含 `UNITY_COLORSPACE_GAMMA`。
- 可选指令：发一行 `{"command":"refresh"}` 会让 Unity 立刻重算一次载荷并广播（排障增强，非协议必需）。
- 读端遇到不认识的事件必须**忽略**而不是报错，给以后的协议扩展留路。
- 断开后直接重连即可：接上时总会先收到一份新的完整快照，不需要握手或版本协商。

一帧长这样：

```json
{"event":"onShaderContextChanged","timestamp":1790779331,"data":{"activeKeywords":["_MAIN_LIGHT_SHADOWS"],"globalDefines":{"defined":["SHADER_API_D3D11"],"undefined":["UNITY_COLORSPACE_GAMMA"]}}}
```

发现文件与协议字段的完整定义见同目录 [`endpoint.schema.json`](endpoint.schema.json)；实现细节见 `MicroShaderBridge/` 下的代码注释。

## 五、安全口径

- 只监听本机回环地址 `127.0.0.1`，不监听对外地址，没有网络暴露面；不需要管理员权限。
- 桥接与语言服务之间流动的数据只在本机回环内，不经过外网、也不发往任何外部服务。
- 最多同时接受 4 个客户端，超出就直接拒绝新连接 —— 先到者胜，不会踢掉已经在工作的读端。

## 六、已知限制（如实声明）

1. `.hlsl` 文件不在桥接的上报范围：桥接只报全局关键字与全局宏；某个 `.hlsl` 文件属于哪个工程，仍由语言服务自己判定。
2. 色彩空间取的是 `PlayerSettings.colorSpace`（编辑器当前色彩空间），不是 `QualitySettings`。
3. 图形 API 取的是**构建目标平台**的 API，不是编辑器自己跑在哪个后端 —— 着色器编译按目标平台走。映射不出的后端一律留空：宁可不注入，也不注入一个猜的宏名。
4. 开关状态按「用户 + 工程」记忆，存在编辑器偏好里、不进 git —— 团队里每个人的开关各自独立。
5. 同一个工程被两个 IDE 窗口打开时，两个语言服务进程都会连上同一个桥接、各自独立记录状态；未做引用计数（互不干扰，但也不统计「谁在用」）。
6. 多实例同机：一个工程一个桥接实例，判据是「发现文件属于哪个工程根」，多工程互不越界。
7. Unity 被强杀或崩溃时会来不及删发现文件。语言服务看到时会提示「发现文件不可信」并退化为无桥接 —— 这是预期行为，不是故障：语言服务不会去删它，下次 Unity 正常启动会覆盖它；想立刻消除提示，重开 Unity 即可。
8. 极端情况下（写入中途被强杀）可能留下 `endpoint.json.tmp`；读端会忽略它，下次写入会覆盖 —— 可以直接无视。
9. 请从 Unity Hub 以普通权限启动 Unity：`-batchmode` 模式能加载工程但不执行编辑器脚本的加载回调，发现文件不会生成；以管理员身份启动时，编辑器会弹出管理员模式告警对话框，自动确认桥接状态会失败（手动使用不受影响）。
